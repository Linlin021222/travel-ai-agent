四、前端配套

  • 按 resultType 自动匹配渲染器：MessageRenderer 依据 resultType + data.chartType 分派到指标卡 / 条形图 / 气泡图 / 表格，新增工具无需改前端分派逻辑。
  • 指标卡组合组件 MetricCardMessage：4 卡布局，复用 Dashboard 卡片样式，大数字走 K/M/B，副行显示「取消率 1.58%」这类量+百分比。
  • 条形图 BarChartMessage：hover 显示「数值 · 占比百分比」，顶部 chip 回显维度/指标/分组数，超过 24 项提示截断。
  • 气泡图 BubbleChartMessage：点击下钻机场层级、返回上一层（zoom in/out），hover tooltip 展示 5 项指标明细。
  • 统一错误提示 ToolErrorMessage：按 code 切换 severity（403 警告、404/409 提示、500 错误），展示工具名与错误码。

五、与上周「校验 + 缓存」的联动

  • 缓存联动：ai:chat_cache: 现在连同 payload 一起缓存——同一问题二次命中缓存时，图表/指标卡照样能还原（已验证：缓存命中 resultType=chart 仍存在）。
  • 审计联动：工具执行复用上周的 ai_operation_audit 表与 scope=all 管理员视图，新增 action tool.execute，管理员可直接查跨用户工具调用记录。
  • 校验联动：工具入参走现有 class-validator DTO 链路，非法参数返回 400 且 message 可直接展示。
  • 会话记忆联动：工具回答同样写入会话历史，刷新页面图表不丢。

六、三处需求偏差（已按合理假设处理，请确认）

  1. 项目里没有 DashboardService：原需求要求「注入现有 DashboardService」。我新建了 dashboard.service.ts 作为门面，但它委托给 FlightDelayService（新增 overview() 复用同一个私有 buildWhere），因此 KPI 与图表口径天然一致，没有复制 SQL。
  2. users 表原本没有姓名/title/role/status 列：只有 id/email/password_hash/时间戳。我写了迁移脚本补齐这 4 列并回填（25 行，管理员角色来自 AI_ADMIN_EMAILS），工具返回字段因此与表完全对齐。
  3. K/M/B 换算规则原本不存在（前端只有 toLocaleString）。我在后端 number-format.ts 定义了唯一规则，前端 lib/format.ts 同源镜像，避免 Dashboard 卡片与 AI 卡片口径漂移。
